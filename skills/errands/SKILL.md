# Errands

Errands go wrong in different ways from code: the cost is the user's time and attention, steps only they can do,
and advice that changes halfway. These habits keep them short.

## Start from the end

- **Look at the actual form or final step first**, before collecting anything. Requirements in policy text and
  guides are paraphrases; the form says exactly which document, in which format, from which source. Open it (read
  only, submit nothing) and list its fields and uploads.
- **Find out how it really goes** from people who did it recently (forums, experience posts, Q&A pages), not only
  from official text: what gets checked, what can be supplied later, how long each stage takes, what is easy to
  miss (fees, taxes, deadlines). Do this before giving advice, so the advice does not flip later.
- Write down the deadlines that come after submission (a window to confirm something, a renewal) as well.

## Facts come from documents

- Take names, numbers and dates from the user's own documents (contracts, payslips, certificates, receipts), not
  from memory or what the user calls things. The legal name of an employer, landlord or school often differs from
  the everyday one.
- Check whose account an app or browser is logged in to before acting through it.
- When a document cannot exist yet (a record not posted, a certificate not issued), say so, say when it will, and
  check whether the process accepts something provisional in the meantime.

## Match effort to the question

- "Where / what is it called / how do I start" is usually answered by a search results page and one good source.
  Skim first; read deeply only when judging credibility or comparing options, when sources disagree, or when a
  mistake would cost money or a deadline.
- Stop when more looking stops changing the answer (new results repeat the old ones, independent sources agree),
  not after a fixed number of sources.
- **Say how you looked**, so the user can judge the answer: skim or deep read; where and with which queries; how
  many results seen and which sources opened; what was left out; how many independent sources back each claim
  and how recent they are; what is still unknown and what looking further would take.
- Prefer the fastest channel that reaches the same thing: an official web page or a desktop browser over tapping
  through a phone app; a direct link over menus.
- Report progress in short steps instead of waiting silently on long jobs.

## The user's part

- Some steps only the user can do (one-time codes, identity checks, payments, signatures, decisions). Find them
  early, batch them, and say exactly what to do and what to send back.
- Read terms before agreeing on the user's behalf and summarize what they commit to.
- Before an irreversible step (submit, pay, send), show the user what will go out and wait for a yes.

## Leave things tidy

- Keep one folder per errand with the documents, numbered in the order the form asks for them, and a checklist
  that records sources, what is missing, decisions, and what happens next.
- Keep sensitive files only where the user keeps them; delete scratch copies, temporary permissions and settings
  changed along the way, and say what was left in place.
